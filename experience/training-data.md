## 一、业务规则

### BR-AI-01：来源身份分层

- `source_kind` 表示来源类别；来源角色、展示标签和调度能力不得互相替代。
- 同一来源的入库、去重、状态和统计断言必须使用稳定身份键。

### BR-AI-02：双入口共享规则

- 定时调度和直接 API 都必须经过相同的解析、去重、持久化和错误处理语义。
- 入口差异只体现在触发方式和返回 envelope，不应产生两套业务结果。

### BR-AI-03：工具池是全集，团队工具是关系

- 工具池保留发现或录入的全部工具；团队工具表示精选关系；用途分类是工具属性或配置映射。
- 取消精选不删除工具实体；删除或失效工具时要验证列表、详情、统计和关系清理。

### BR-AI-04：安全配置不进入业务日志

- GitHub token、密钥和完整授权头只能通过安全配置注入。
- 请求失败、重试和错误响应中不得回显凭证或敏感 header。

### BR-AI-05：执行证据分层

- 用例设计门禁只能证明覆盖、结构和可执行性。
- Go/Vitest/Playwright、真实数据库、调度器和浏览器结果必须单独记录，不能由静态检查推断。

## 二、Few-Shot 参考

### 例 1：测试点集合闭环

`分析文档测试点全集 → 分类用例 → 汇总 → 集合差集 → 门禁报告`。任何缺失测试点必须补用例或明确排除理由。

### 例 2：异常断言优先

对配置保存、来源拉取和工具发现，至少同时验证成功、空数据、非法参数、依赖失败、重复数据和敏感信息不泄漏。
